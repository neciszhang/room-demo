# 原小屋模型优化

优化文件：`public/models/room-optimized.glb`。原首页继续加载同一路径。

## 结果

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 场景三角面 | 633,516 | 180,870 |
| GLB 文件 | 7,739,492 bytes | 4,192,092 bytes |
| 模型与外观资源加载量（不含 JS、缩略图） | 11,539,681 bytes | 6,573,196 bytes |
| 实际材质引用贴图显存估算 | 144.83 MiB | 108.83 MiB |
| 交互分组 / 动画 | 16 / 19 | 16 / 19 |

贴图显存按 RGBA8 + 完整 mipmaps（4/3）计算，包含彩色、白模烘焙贴图；不包含阴影、帧缓冲、几何和驱动开销，非真机 VRAM 测量。最终浏览器主渲染统计为 32 calls / 180,870 triangles；阴影等额外 pass 不包括在该值内。

## 处理内容

- 使用 glTF Transform + Meshoptimizer 对独立静态物体减面，保留节点名称、collectible/lightmap 元数据、层级及所有动画。
- 星星的原始网格、骨骼权重、绑定矩阵和动画采样数组完整保留；读取压缩输出后逐项哈希校验。
- 背景墙减面曾引入可见的烘焙瑕疵，最终保留背景墙原始网格。交付约 18.09 万三角面，满足 20 万上限，没有达到 10 万目标。
- 移除原页面不使用的静态物体法线贴图。动态星星和小花仍保留法线贴图。
- 部分较小道具的颜色贴图降到 512，其余保留原分辨率；所有模型贴图不超过 1024。
- 星星原外置 PNG 颜色贴图转成无损 WebP 嵌入 GLB，取消配置中的重复外置加载。旧 PNG 留作来源文件，运行时已不请求。
- 不再请求动态物体未使用的两套烘焙光照图；原图片文件保留。
- 保持原有 Meshopt 压缩（EXT_meshopt_compression），无需新增 Draco 解码配置。

## 验证与恢复

- Chrome 桌面模拟 414×896、375×667：白模、全彩预览、无横向溢出。
- 16 件物体逐一点击、激活动画、全部点亮、3 段 idle、旋转后恢复相机，以及 `/star-reading` 原有路由回归。
- 19 段动画曲线、节点变换/层级、1 套皮肤绑定、星星几何校验一致。
- `npm run build` 通过；控制台无加载错误。
- 尚未在真实手机上测量帧率、发热及内存峰值。

本地证据位于 `evidence/original-room-optimization/`，包含优化报告、浏览器截图、原 GLB 与配置备份。可复跑脚本位于 `.asset-tools/optimize-original-room.cjs`、`check-original.mjs`、`verify-original-interaction.mjs`；它们引用本机已安装的 glTF Transform 和 Playwright 环境。这两个目录被 Git 忽略，不随项目发布。
